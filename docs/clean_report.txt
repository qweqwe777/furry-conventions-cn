清洗报告
================================================================
输入  : fec_snapshot_20261017.csv  511 行 × 34 列
输出  : fec_events_clean.csv  见下方列清单

[规则 1] 排序：start_date → end_date → event_key 升序。
         派生列（第 N 次、是否重复）以此顺序为准；换顺序结果会变。

[规则 2] venue_type = locationType，缺失时取 place_kind。
         取自 locationType 411 行；取自 place_kind 92 行；两列皆空 8 行。

[规则 3] region 由源站 macro_region 映射：台湾→台湾，港澳→香港，其余→中国大陆。
         中国大陆 443 / 台湾 65 / 香港 3。
         说明：源站 country 列把台湾与大陆并列为国家值，本数据集不沿用该列。
         宜兰、南投两条在源站 country=中国 而 macro_region=台湾，按 macro_region 归入台湾。

[规则 4] days 由起止日期重算：(end_date - start_date).days + 1，含首尾。
         重算值与源站 days 列不一致 7 行，以重算值为准，
         源站原值保留在 days_published 列。负值 1 行、
         单日展会 153 行、超过 14 天 1 行——见 known_issues。

[派生列] 全部按上面的排序顺序累加，不是源站字段：
  is_repeat_city     该城市在本数据集中此前是否已出现过一次展会
  is_repeat_org      该主办方（org_slug）此前是否已出现过一次
  first_year_in_city 该城市在本数据集中的首个展会年份
  org_event_seq      该主办方在本数据集中的第几场（从 1 起）
  same_name_city_seq 同名同城在本数据集中的第几场（从 1 起）
  name_is_year       名称就是一个四位年份（源站如此，非抓取损坏）

[规则 5] info_source 直接沿用源站 source_names（信息出处：WikiFur / QQ空间 / 官方微博等），
         缺失率较高，仅作溯引用途。

[规则 6] type 缺失 172 行（33.7%），留空不推断。

[规则 7] name_is_year 命中 11 行：源站该条目的名称就是一个年份，
         本数据集不替它编名字，仅打标记。
